# S3-ZK-0053 - Workflow provenance is execution provenance

## Claim

A Git ref carries automation policy as part of its execution state. The
workflow definitions applicable to the exact proposed ref and event, together
with the changed paths, determine whether a remote write can start Actions;
the workflow state of `main` is not evidence for a non-main write.

## Evidence class

`S3_MEASURED` and `INFERENCE`.

## Evidence

At production `main=631b51e70562a33183ac14d0be5bbe2ddd140779`, `tests.yml`
restricted `push` to `main` and production-relevant paths. At the research
head `06ed79449dcd917c3213570389a3639f6ad0be24`, the same workflow had an
unrestricted `push`. The research push created Actions run `31748403817`.
A local bounded simulation reproduces the old state as
`ACTIONS_POSSIBLE` and the proposed local trigger repair as
`PROVEN_ZERO_ACTIONS`, without another remote write.

## Consequence

Remote-write safety must be evaluated as:

```text
(PROPOSED_REF_STATE, EVENT, DIFF)
```

The trigger proof is separate from authorization. Even
`PROVEN_ZERO_ACTIONS` does not authorize publication when the current
campaign forbids remote writes.

## Falsifier

An independently validated event model showing that workflow definitions from
an unrelated ref determine the push event, or a counterexample to the local
old-state/repaired-state distinction, would falsify this bounded claim.

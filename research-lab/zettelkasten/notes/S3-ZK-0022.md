# S3-ZK-0022 — Optimization facts should survive as explicit proof objects when profitable

TYPE: ARCHITECTURE
STATUS: OPEN

## Thesis

Facts proved by one compiler phase should not be silently discarded if later phases could safely exploit them. A compact proof/fact record can preserve knowledge across lowering boundaries.

## Source basis

Logic in Tehran includes work on quantifier elimination, explicit definability, bounded arithmetic and links between syntactic formula classes and computational complexity. These results do not prescribe compiler metadata, but they reinforce the distinction between what is expressible/provable and what a later consumer can decide cheaply.

## S3 inference

Potential metadata shape:

```text
FACT_ID
VALUE_ID
PROPERTY
DERIVED_BY
VALID_REGION
DEPENDENCIES
INVALIDATORS
```

Examples:

```text
NON_NEGATIVE
RANGE[a,b]
NONZERO
SAME_LOGICAL_VALUE
MEMORY_VERSION_VALID
REPRESENTATION_EQUIVALENT
```

Later passes may consume the fact instead of rediscovering it.

## Guardrail

This is not permission for an unbounded theorem prover in normal compilation. Facts must have bounded validation cost and explicit invalidation semantics.

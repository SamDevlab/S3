# S3-ZK-0050 - First useful work is measured at the process boundary

## Claim

For a native S3 program, the first correct output can be measured externally,
but a launch timer is not a measurement of S3-controlled startup by itself.

## Evidence

On the exact P7 production head, nine tiny workloads were launched 15 times
each. Emulator and native results matched for constants, arithmetic, branch,
call, trit, tryte, f64, reference and slice programs. Median first-output
latency ranged from 1,037,589 ns to 1,288,280 ns. Cold-cache state was not
controlled, and the timer included process launch and loader work.

## Consequence

The result is a reproducible first-useful-work baseline, not proof of an S3
startup bottleneck. A future startup target needs an attribution harness that
separates external process/loader cost from generated entry, S3 runtime fixed
cost and user computation.

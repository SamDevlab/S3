# S3-ZK-0024 — Ternary representation selection is a conversion-graph problem

TYPE: HYPOTHESIS
STATUS: OPEN

## Thesis

If a trit can inhabit multiple valid physical representations, transitions between them have costs. Representation selection should therefore consider the whole use region, not greedily choose a format at each instruction.

## Source basis

Babu's ternary processor examples require conversion between physical ternary substrates in some architectures, making representation conversion explicit. Network-flow/combinatorial literature already in the research corpus provides tools for optimizing paths/costs once the S3 problem is modeled correctly.

## S3 inference

Model representations as nodes:

```text
SIGNED_SCALAR
PACKED_2BIT
DENSE_BASE3
VECTOR_MASK
CANONICAL_MEMORY
```

and conversions as weighted edges. Operations constrain the allowed representation set at each program point.

Research questions:

- shortest-path representation conversion for a single linear use chain;
- dynamic programming over expression DAGs;
- CFG/global coupling when values cross joins/loops;
- interaction with register pressure and materialization.

Do not add dense/packed representations until measured workloads justify conversion complexity. The graph model may remain an oracle/analysis tool first.

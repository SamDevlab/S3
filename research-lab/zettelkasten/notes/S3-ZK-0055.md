# S3-ZK-0055 - Path-complete necessity is independent of dynamic hotness

## Claim

A dynamically hot initialization check can be a bounded accidental population
without becoming a safe production rewrite. Static path proof, public runtime
contracts, and native effect must be established independently.

## Evidence

On the exact P7 production head, definite non-address-taken register-init checks
accounted for 1,660 observed events across 11 workloads. The conservative model
still left 320 of 1,587 static sites unknown, the existing emulator could not
trace TADDR, and no native instruction or memory reduction was measured.

## Consequence

Dynamic weighting selects where to investigate; it does not carry a proof across
the Assembly/runtime boundary. P8.3 therefore remains
`NO_VALID_TARGET_YET`. A future candidate needs proof transport, checked
fallback, and a direct emulator-cost measurement.

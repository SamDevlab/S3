# S3-ZK-0016 — Ternary semantic abstraction must precede physical encoding

TYPE: ARCHITECTURE
STATUS: OPEN

## Thesis

An S3 `trit` should remain a semantic three-valued object for as long as profitable. Its physical encoding (`signed byte`, `2-bit packed`, `dense base-3`, mask/vector form, canonical memory form) is a backend representation decision, not the identity of the source value.

## Source basis

Gottwald distinguishes systems by their truth-degree structures and emphasizes that many-valued semantics are determined by truth-degree functions/connectives rather than by one privileged physical encoding. Babu's multiple-valued computing volume demonstrates that ternary logic can be realized across very different physical substrates and still expose ternary operations/components.

## S3 inference

Preserve:

```text
SemanticTrit
  -> RepresentationChoice
       -> scalar | packed | vector | memory
```

instead of lowering immediately to a binary integer convention.

## Falsifier

If keeping ternary semantics explicit through the relevant backend layers increases complexity without enabling lower conversion cost, smaller code, less memory traffic, better packing, or stronger simplification on representative workloads, this architecture should remain research-only.

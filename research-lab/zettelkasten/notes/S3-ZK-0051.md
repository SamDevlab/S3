# S3-ZK-0051 - Initialization state is an observed native commitment boundary

## Claim

The native backend commits to initialized-state bytes before many ordinary
value operations, and those bytes cannot be called accidental merely because
they are metadata-shaped.

## Evidence

The exact P7 native disassembly shows per-register initialization stores,
memory reset operations and per-instruction limit checks before the loop body.
The current focused corpus passes controlled uninitialized-register and
uninitialized-memory diagnostics, bounds/failure timing, and instruction-limit
tests. These observers make a blanket removal rule unsound.

## Consequence

Initialization-state optimization requires a path-complete proof over failure
exits, memory validity, aliases, calls and instruction-limit ordering. Static
frequency alone is not an obligation witness. The current classification is
NECESSARY_OR_UNKNOWN, not removable.

## Status

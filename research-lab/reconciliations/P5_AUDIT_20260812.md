## Metric correction

P4's `metadata_accesses=5638` is defined by the external probe as every
generated line containing `byte ptr [rbp`. It is a lexical byte-frame metric,
not a semantic metadata type. Independent region-aware decomposition on the
same base and external JSMN source reproduced the exact total in RA_OFF and
RA_ON:

```text
REGISTER_INITIALIZATION=4589
MEMORY_INITIALIZATION=837
TRIT_ARRAY_DATA=212
TOTAL=5638
```

Thus `5426` accesses are initialization/definedness state and `212` are
semantic trit payload accesses accidentally included by the broad metric.

The memory-state portion is `228` TLOAD checks, `96` immutable-store checks,
and `513` initialization stores. Register-state traffic is `1549` read checks,
`1514` body marks, and `1526` prologue zero/parameter marks.

## State interpretation

The emitter has explicit initialized bytes but no independent memory-validity
bit. A physical register can be current while its canonical frame value is
stale until `_snapshot_register`; this makes a dual-validity/reduced-product
model useful, but does not prove that all state checks are removable.

The native failure contract requires preservation of uninitialized-register,
uninitialized-memory and immutable-write behavior. Exact required versus
conditionally avoidable shares, dead metadata stores and dynamic weights were
not measured and remain null in `P5_AUDIT_RESULT.json`.

## Research decision

The strongest measured target is not a generic RA rewrite or SSA-only pass.
The recommended future capability is:

```text
P5 - Proof-Preserving Initialization State and Lazy Materialization
```

It should preserve verifier-backed initialization facts and materialize native
state only at actual observers. Cross-workload provenance and dynamic weighting
remain promotion gates. No production code, PR, CI gate, full suite, benchmark,
shutdown or P6 was started.

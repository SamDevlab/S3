## Causal result

P4 did **not** establish poor allocator quality as the primary problem.

It established a more specific configuration/representation cause:

```text
EARLIEST_LOCATION_FLEXIBILITY_LOSS=
X8664Backend.register_allocation default false

EARLIEST_MEMORY_IDENTITY_LAYER=
emitter frame canonicalization after the default backend selected RA_OFF
```

The existing deterministic whole-function liveness-aware allocator already had enough machinery to preserve eligible values globally. The production transformation therefore made register allocation the native default while preserving `register_allocation=false` as an explicit stack-backed diagnostic/fallback mode.

Final corrections also resolved local TMOV aliases in call snapshots and skipped dead incoming parameters during physical entry initialization.

No allocator redesign, phi rewrite, Assembly IR redesign or benchmark-specific path was introduced.

## Research consequences

P4 resolves the central causal question behind `S3-EXP-0002` at production scale:

- allocator **enablement/default policy** was a major cause of avoidable frame traffic;
- allocator **quality itself** was not established as the primary cause;
- frame traffic and memory-state metadata traffic must now be analyzed separately;
- the next production target should not be a generic RA rewrite.

Residual diagnosis:

```text
RESIDUAL_PRIMARY_BOTTLENECK=REPEATED_MEMORY_STATE_MATERIALIZATION
NEXT_RECOMMENDED_TARGET=SSA_DESTRUCTION_AND_MEMORY_STATE_METADATA_STAGING
```

This should be reconciled with the research-lab information-preservation and SSA literature before defining P5.

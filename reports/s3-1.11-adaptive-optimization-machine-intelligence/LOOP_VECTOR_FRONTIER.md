## Exact recognizer boundary and first rejection points

The source contains recognizable counted-loop syntax: `period = period + 1`,
`point = point + 1`, and nested `column`/`row` unit increments. This source
shape alone is not a vectorization proof. The existing recognizer is narrower:
`_recognize_induction` requires one natural-loop backedge equal to its selected
body block, one preheader, a body ending in a direct jump to the header, and
no jump/branch/return inside that body. It further requires an exact
single-cell induction memory recurrence with a constant positive step.

The measured CFG loop bodies span 6 to 57 blocks. The energy/point-cloud
primary loops include nested match/relation/switch continuation blocks; the
raster loops include nested-loop and match control. Thus the first
demonstrated analysis boundary is multi-block control/continuation shape,
not an established absence of source-level counted loops. The predicate trace
now identifies the exact first failed recognizer gate for each loop:

| Workload / header | First failed predicate | Relevant CFG fact |
| --- | --- | --- |
| energy / `while_condition_32` | `BACKEDGE_TAIL_DIFFERS_FROM_SELECTED_BODY` | selected `while_body_33`; backedge `switch_continue_52` |
| point cloud / `while_condition_29` | `BACKEDGE_TAIL_DIFFERS_FROM_SELECTED_BODY` | selected `while_body_30`; backedge `switch_continue_61` |
| point cloud / `while_condition_62` | `INDUCTION_STORE_COUNT_NOT_TWO` | candidate memory 16 has four function-wide stores; this loop has one update plus one preheader initializer |
| raster / `while_condition_59` | `BACKEDGE_TAIL_DIFFERS_FROM_SELECTED_BODY` | selected `while_body_60`; backedge `while_exit_72` |
| raster / `while_condition_68` | `BACKEDGE_TAIL_DIFFERS_FROM_SELECTED_BODY` | selected `while_body_69`; backedge `switch_continue_120` |

The point-cloud cell is reused by sequential loops: its four stores are in
`switch_negative_26`, `while_exit_33`, `switch_continue_61`, and
`while_body_63`. The existing recognizer counts stores function-wide, so an
otherwise local two-store recurrence is rejected by that gate. This exact
predicate does not itself justify weakening the production check.

## Continuation-aware recurrence probe

An analysis-only bounded CFG reachability probe follows all IR branch targets
from the selected body to a backedge, saturates candidate induction-update
counts at `2+`, and tracks other writes to the candidate memory. All five
loops reach their backedge with exactly one recognized positive-constant
update in every reachable abstract backedge state. For the point-cloud inner
loop, the census independently shows one local update plus one preheader
initializer; unrelated updates in the other sequential loop account for the
function-wide store count of four.

This is structural recurrence-shape evidence only. It does not prove edge
feasibility, termination, initial-value semantics, non-escape, bounds, alias
safety, inter-iteration memory dependence, or SIMD legality. All five loops
remain `UNKNOWN`; no vector code is authorized. The result motivates a
future narrow continuation-aware recognizer investigation, but this campaign
has not changed production loop analysis.

## Guarded scalar slice-bound proof

`EXP-S3-111-GUARDED-SLICE-BOUNDS-001` adds an analysis-only, fail-closed
source/IR check for the energy and point-cloud workloads. It recognizes the
actual guard path in the parsed source, checks the compiled `SLICE_LOAD` index
type and source location, and requires a zero preheader initializer plus a
unit recurrence update on every abstract CFG backedge. It does not modify the
optimizer, emitter, or runtime bounds checks.

For energy, the `period_count > 364` arm clamps to zero and the subsequent
`period_count <= 0` guard returns; every path reaching the loop therefore has
`1 <= period_count <= 364`. The loop initializes `period` to zero, tests
`period < period_count`, and advances by one. `load_count == period_count`
ties the second slice length to the same bound. Thus both loop reads have
indices `0..363`, within the tryte range `[-364, 364]` and their respective
slice lengths.

For point cloud, `point_count > 121` sets the bounded count to zero and the
subsequent nonpositive guard returns, so a path reaching either loop has
`1 <= bounded_point_count <= 121`. The successful `coordinate_count ==
bounded_point_count * 3` guard establishes a coordinate length from 3 through
363. The three pre-loop seed reads at indices 0, 1, and 2 are within that
length. Each counted loop starts `point` at zero, tests it against the bounded
count, and advances by one. Its three reads use `3*point`, `3*point+1`, and
`3*point+2`, giving ranges `0..360`, `1..361`, and `2..362`. The largest
index is both below the guarded length `3*n` and inside the tryte domain.

The result is 11 proven scalar slice reads: 2 energy accesses, 3 point-cloud
seed accesses, and 6 point-cloud loop accesses. The Linux JSON is pinned to
S3 control `832b1cc04fe1f6174e482eb3a245e08af3d53211`, tree
`dc1138890655169088f9371ce32a9050cfc3af8d`, Python 3.14.4, and has SHA-256
`4f73ebbb31760f0d984ee48168dd1fa1dd1dd7806b5469ca51fafdecbd3b5558`.
Focused negative tests raise the energy cap beyond the tryte domain and invert
the point-cloud length relation; both cases return `UNKNOWN` rather than a
proof.

This closes a scalar access-bounds gap for these two exact guarded programs; it
does not establish aliasing or inter-iteration dependence. The raster bounds
were still unresolved in this experiment and are addressed separately below.
The vector result remains unchanged: all five loops are `UNKNOWN`, with no
whole-loop independence proof and no SIMD authority. The recognizer is bounded
to the stated source/IR forms, not a general range analysis.

Even with induction and scalar bounds recognized, the analyzer does not model
general inter-iteration memory dependence. In particular, raster conditionally
accumulates and retains scalar recurrences; access bounds alone do not prove
vector legality. `UNKNOWN` remains the correct fail-closed vector result and
SIMD is not justified.

## Address recurrence candidate

`EXP-S3-111-ADDR-RECURRENCE-001` used the proven point-count and coordinate
length guards to test one research-only candidate: initialize a tryte base to
zero before the first counted loop, reset it before the second, then advance
it by three per iteration. The exact source diff and Linux native evidence are
retained in the experiment JSON. Reference output and native status/output
matched for counts 0, 1, 64, 121, 122 and a coordinate-length mismatch. The
checked recurrence stays within tryte range through the final post-body
increment (363 at the maximum count).

The candidate did not improve native structure: `.text` increased by 408
bytes, static instructions by 32, memory references by 8, branches by 12,
stack references by 9, and frame size by 16 bytes. Peak-live remained 7 and
static stack residency remained zero. Its 21-sample paired timing is
inconclusive (baseline/candidate median ratio 1.0457; percentile interval
[0.9801, 1.1053]), so no runtime direction is claimed. This recurrence is
rejected structurally and is not wired into production.

## Slice-memory dependence and call effects

`EXP-S3-111-LOOP-MEMORY-DEPENDENCE-001` closes a narrower question on the exact
O1 IR for all five natural-loop regions. It finds zero `SLICE_STORE` and zero
`REFERENCE_STORE` instructions in every region. Calls inside a region are
accepted only when their effect closure is known: the energy and raster loops
call local `absolute_f64`, whose complete in-module body has scalar-only
parameters/registers, local frame memory, and no reference/slice operation or
unresolved call. Unknown, external, reference-bearing, or mutating call paths
fail closed; focused negative tests inject a slice store and an unresolved
call and verify that neither is classified read-only.

The bounded result is therefore **no loop-carried write dependence on
slice/reference storage** for these five exact IR regions. Input slice aliasing
is not a write conflict when the loop regions only read those slices. This is
not whole-loop independence: each region still has local scalar stores (20,
29, 9, 47, and 42 respectively), including induction/accumulator state, and
the probe does not solve branch feasibility, strict-FP reduction legality,
complete scalar dependence, or all bounds. Whole-loop independence remains
`NOT_PROVEN` for 5/5; vector legality remains `UNKNOWN` and vectorization is
not authorized.

## Guarded raster scalar bounds

`EXP-S3-111-RASTER-BOUNDS-DIAGNOSTIC-002` closes the four scalar raster
access bounds without changing the vector-legality result. The analyzer
recognizes the two nested loops only when their source conditions are
`row < bounded_height` and `column < bounded_width`, their IR recurrences
start at zero and update by one on every abstract backedge, and the guarded
dimensions/count are positive and at most 364. On the true arm of
`cell_count == bounded_width * bounded_height`, it records the symbolic
product relation. Since the loop facts give
`0 <= row < bounded_height` and `0 <= column < bounded_width`, the base index
`row * bounded_width + column` lies in `[0, cell_count - 1]`, hence `[0, 363]`.
The `mask_count == cell_count` guard ties the mask length to the same upper
bound; `values` already uses `cell_count` as its length.

The neighbor loads are proven only on the true arm of the strict guard
`to_tryte(column + 1) < to_tryte(bounded_width)`. Nonnegative `column`,
positive width/height, the row-major relation and this strict inequality keep
`index + 1` in `[1, cell_count - 1]`. A non-strict guard is insufficient at a
row boundary. Regressions that invert the product equality, weaken the strict
guard to `<=`, or reassign a dimension before access all return `UNKNOWN`.
Symbolic product/length/induction facts are invalidated on modeled assignment.

The source-pinned Linux JSON is
`evidence/control-832b/EXP-S3-111-RASTER-BOUNDS-DIAGNOSTIC-002.json`, SHA-256
`df6be866601bfcbc8374bcfe9d0ed9a54ecd789e40a706e7d46885c00ca16676`. It
records 2/2 recurrence proofs and 4/4 scalar bounds. This is a bounded proof
for the pinned source shape, not a general symbolic range engine. It does not
prove the loop's scalar recurrences independent, resolve branch feasibility,
or authorize vectorization; whole-loop independence remains unproven for all
five loop regions.

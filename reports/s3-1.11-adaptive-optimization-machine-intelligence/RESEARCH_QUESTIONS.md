# S3 1.11 Research Questions

Statuses below are the experiment-backed closure status for the frozen 1.11
campaign. `OPEN` means the question remains unanswered; it is not a failed
gate or permission to start the next campaign.

| RQ | Question | Closure status | Evidence and remaining boundary |
| --- | --- | --- | --- |
| 1 | Can value locality be pressure-aware enough to avoid the 1.10 raster trade-off? | PARTIAL | SSA substitution is structurally selected for energy/point cloud and raster is rejected. STORE→LOAD point-cloud shows a replicated material timing signal on exact binaries, despite pressure/memory trade-offs; the conservative guard rejects it, so performance-aware authority remains open. |
| 2 | Can liveness shrinking improve code after value substitution? | PARTIAL | `EXP-S3-111-LIVE-001` finds CFG-aware live-boundary incidence increases under both existing transforms, with STORE-to-LOAD also increasing peak live by 3/5/3. No lifetime-shrinking transform has been tested yet. |
| 3 | Which native move categories dominate hot regions? | PARTIAL | Broad MOVE weights are 51,326 / 43,064 / 28,594; bounded hot-block opcode associations are mapped. A same-color Assembly-copy prototype removes 30 native copy bodies structurally, but semantic/ABI/allocator causes of the broader MOVE category remain unavailable. |
| 4 | Can a proven machine-copy class be safely coalesced? | SUPPORTED_STRUCTURALLY | `EXP-S3-111-MOVE-COALESCE-002` omits 30 allocator-proven same-color TMOV data bodies, preserves PER accounting and exact outputs, and reduces static instructions/text; timing is not materially improved. General coalescing remains untested. |
| 5 | Which control categories dominate hot execution regions? | PARTIAL | Branch mnemonics/opcode lineage are joined to hot-block visits; user/loop/bounds/budget/error roles and taken edges remain unproven. |
| 6 | Can hot layout or cold-path separation improve native structure or timing? | PARTIAL | `EDGE-PROFILE-002` has exact single-successor counts for 26 edges in the reported top-20 hot-block subsets while explicitly leaving 93 conditional edges unknown. `HOT-FALLTHROUGH-001` uses one 168-execution energy backedge, removes one static branch/instruction and two `.text` bytes, and passes independent Bench correctness/structure replay; paired timing is within ±5%, so no material runtime effect is established. More workloads/edges and cold-path separation remain open. |
| 7 | Are there profitable affine address-strength-reduction sites? | PARTIAL | Bounds establish two point-cloud loop sites. `ADDR-RECURRENCE-001` preserves native outputs/status but worsens `.text` by 408 bytes, adds 32 instructions, 8 memory references, 12 branches, 9 stack references, and 16 frame bytes; timing is inconclusive. The tested recurrence is rejected structurally; other address forms remain open. |
| 8 | Can loop canonicalization reduce vector-legality UNKNOWN? | PARTIAL | `LOOP-PREDICATES-001/002` finds four first failures at backedge/body mismatch and the point-cloud inner loop at a function-wide store-count gate despite one loop-local update plus one preheader initialization. `LOOP-RECURRENCE-001` finds one positive update in each reachable abstract backedge state for all five; production recognition and source-level induction remain unproven. |
| 9 | Can dependence analysis prove any current loop vectorizable or illegal? | PARTIAL | `GUARDED-SLICE-BOUNDS-001` proves 11 scalar bounds in energy/point cloud; `RASTER-BOUNDS-DIAGNOSTIC-002` proves the four raster scalar bounds using guarded row-major/product and strict-neighbor facts. `LOOP-MEMORY-DEPENDENCE-001` finds no loop-carried writes to slice/reference storage in five pinned O1 regions. Whole-loop independence remains unproven for 0/5 because scalar recurrences, branch feasibility, and strict-FP reductions remain unresolved. Vectorization remains unauthorized. |
| 10 | Does a proven hot loop justify a first SIMD experiment? | DEFERRED_WITH_EVIDENCE | No loop currently proven vectorizable. |
| 11 | Can a multi-objective model reject harmful transforms before timing? | PARTIAL | The strict Pareto/pressure guard rejects STORE→LOAD where memory refs grow (+48/+3/+228), despite the replicated point-cloud characterization signal. A narrower same-color emission prototype strictly improves measured static dimensions without pressure change but has no material runtime result. The guard is conservative, not a validated predictor. |
| 12 | Do structure metrics predict runtime direction after adding pressure/move/control facts? | PARTIAL | SSA substitution changes structure without material timing change. STORE→LOAD point cloud has a replicated material signal despite worsened traffic/pressure, while removing 17 same-color copy bodies has no material timing result. No causal microarchitectural attribution exists. |
| 13 | Can O2 experimental isolate aggressive passes without changing O1? | OPEN | No concrete pass set yet. |
| 14 | Does current Assembly block a concrete useful machine transform? | DEFERRED_WITH_EVIDENCE | `ARCH-001` checks same-color copy, SSA-value, and address-recurrence candidates: all were representable in existing source/IR/Assembly research paths; none was blocked by Assembly. |
| 15 | Would a bounded Machine IR solve such a concrete blocker? | DEFERRED_WITH_EVIDENCE | No concrete Assembly representation blocker exists in the tested candidates; no Machine IR prototype is justified. |
| 16 | Does a real memory problem now require MemorySSA? | DEFERRED_WITH_EVIDENCE | STORE→LOAD analysis found candidate sites, but its emitted candidate regressed memory references and pressure; no concrete useful transform is blocked by lack of MemorySSA yet. |

The local preflight does NOT run a native local Stage1 and does NOT mutate/promote the canonical source.

Important new local gate:
The old native snapshot recorded local_count=23, but that number is NOT used as a new local-record capacity by assumption. The local preflight mirrors the Stage1 lexer/hash model and requires the fresh native parameter-candidate report to agree with:
- every Stage1 identifier hash 87 token;
- literal `mut` count;
- supported `mut name: type = ...` / `mut name: type[N] = ...` declarations;
- numeric-token/value count;
- structural event count;
- call count.

If those do not agree, the correct result is:
LOCAL_STATIC_PREFLIGHT=BLOCKED_STAGE1_NATIVE_LEXICAL_MODEL_MISMATCH
LOCAL_NATIVE_QUALIFICATION_ALLOWED=False
LOCAL_NEXT=RECONCILE_NATIVE_LOCAL_VALUE_EVENT_CALL_COUNTS_BEFORE_LOCAL_IR_V2

That is a valid fail-closed result, not a test harness failure.

Local record candidate now preserves:
- owner function ID;
- name identity;
- type ID;
- mutability;
- storage kind (scalar or fixed array);
- per-function local ordinal;
- fixed-array extent;
- semantic value ID.

A physical byte/frame offset is deliberately NOT frozen in semantic IR. The future emitter owns deterministic physical layout.

The local candidate capacity is selected from its exact self-source local-record requirement after the parameter report is validated. It is NOT fixed to 23 or 64. One non-banked lane is allowed only up to 365 records; above that the preflight routes to a measured banked-local design.

Storage/block strategy:
- reuse four existing 365-slot AST/event banks as candidate physical IR-v2 instruction storage only after the legacy event verifier;
- audit the same storage assumption on the exact compaction+parameter candidate before native work;
- reuse four existing 365-slot value banks only after an explicit semantic namespace rebuild;
- candidate block capacity is 730 by reusing two existing i64[365] block arrays as packed block banks;
- packed block owns function owner, terminator kind, target A/B, condition value ID and return value ID;
- instruction record is OWNERLESS: block/opcode/operandA/operandB/result/aux IDs;
- instruction owner is derived via block_id -> packed block owner;
- ownerless instruction max at 730 blocks is 213156320415447743, within signed i64;
- the rejected ownerful layout requires 13855160827004103359 and exceeds signed i64;
- aux is an ID/reference only, not an arbitrary raw i64 payload;
- event -> IR-v2 instruction mapping/in-place rewrite still requires a new native IR-v2 verifier.

The initializer audit only quantifies source structure. A large count of all-zero initializer items is NOT automatically value-pool headroom. Any aggregate zero-init transform still requires a native Stage1 candidate proving identical behavior and reduced semantic value usage.

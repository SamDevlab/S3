Storage-reuse strategy prepared before native qualification:
- reuse the four existing 365-slot AST/event banks as a candidate physical IR-v2 instruction stream instead of adding four new large arrays;
- reuse the four existing 365-slot value banks for the later unified value namespace;
- keep existing block target arrays and repack ir_block_terminator with kind/condition/return IDs;
- link call result IDs through the IR-v2 instruction record instead of adding a 730-entry call-result array;
- mixed-radix instruction record was selected specifically so owner/block/opcode/operandA/operandB/result/aux IDs fit inside signed i64;
- aux is an ID/reference only, not an arbitrary raw i64 payload.

The initializer audit only quantifies source structure. A large count of all-zero initializer items is NOT automatically value-pool headroom. Any aggregate zero-init transform still requires a native Stage1 candidate proving identical behavior and reduced semantic value usage.

Compaction qualification is fail-closed and models its intentional source deltas:
- 2 assignment statements removed from the self-source;
- 1 numeric literal removed;
- parameter/call/discard/control structure invariants remain checked;
- static projections are never substituted for native measurements.

The prepared parameter phase uses ONE packed i64[64] lane instead of five separate arrays, encoding:
owner_function_id + name_identity + type_id + abi_index + value_id.

If the parameter candidate passes, the next-phase planner reserves:
parameters = [0, parameter_count)
locals = [parameter_count, parameter_count + local_count)
first dynamic instruction/constant/result value ID = parameter_count + local_count
and computes headroom from the ACTUAL native parameter-candidate audit.

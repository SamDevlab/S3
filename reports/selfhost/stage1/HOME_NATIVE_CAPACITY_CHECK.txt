Storage/block strategy prepared before native qualification:
- reuse the four existing 365-slot AST/event banks as candidate physical IR-v2 instruction storage only after the legacy event verifier;
- audit that same storage assumption on the exact compaction+parameter candidate before native work;
- reuse the four existing 365-slot value banks only after an explicit semantic namespace rebuild;
- candidate block capacity is 730 by reusing two existing i64[365] block arrays as packed block banks;
- packed block owns function owner, terminator kind, target A/B, condition value ID and return value ID;
- instruction record is OWNERLESS: block/opcode/operandA/operandB/result/aux IDs;
- instruction owner is derived via block_id -> packed block owner;
- ownerless instruction max at 730 blocks is 213156320415447743, within signed i64;
- the rejected ownerful layout would require 13855160827004103359 and exceeds signed i64;
- aux is an ID/reference only, not an arbitrary raw i64 payload;
- event -> IR-v2 instruction mapping/in-place rewrite still requires a new native IR-v2 verifier.

The initializer audit only quantifies source structure. A large count of all-zero
initializer items is NOT automatically value-pool headroom. Any aggregate
zero-init transform still requires a native Stage1 candidate proving identical
behavior and reduced semantic value usage.

Compaction qualification is fail-closed and models its intentional source deltas:
- 2 assignment statements removed from the self-source;
- 1 numeric literal removed;
- expected compacted structural values: 1212;
- expected compacted assignments: 73;
- static projections are never substituted for native measurements.

The prepared parameter phase uses ONE packed i64[64] lane instead of five
separate arrays, encoding:
owner_function_id + name_identity + type_id + abi_index + value_id.

Semantic value-ID plan is intentionally separate from the legacy structural
numeric-token stream:
parameter fixed domain = [0,64)
parameter IDs actually used = [0,parameter_count)
local IDs = [64,64+local_count)
first dynamic instruction/constant/result ID = 64 + local_count

The current legacy ir_value_records overlap these planned semantic IDs. They
must be rebuilt/rebased under a separately qualified namespace transform; they
must never be silently reinterpreted as collision-free semantic IDs.

Current local behavior in Stage1 is only structural: keyword identity 87 (`mut`)
increments local_count and produces event opcode 6. Name/type/owner/frame/value
metadata is not yet retained. The local design audit proposes one packed i64[64]
lane and a scalar current-function frame-slot counter, but LOCAL_TRANSFORM remains
NOT_IMPLEMENTED until the exact candidate preflight exists.

# Roadmap 0.38 — S3 self-hosted assembly renderer (simple_call)

**Status:** closed

---

## Initial attempt (rejected)

The first version of `assembly_renderer_simple_call_text.s3` used golden replay:
- 3,159 lines, 215 literal `return <byte>` statements
- 32-entry text fragment table encoding the entire 448-byte fixture output
- Generated by `gen_simple_call_text.py` (Python script), not written by hand
- Literal/structural byte ratio: 0.48
- Architecture: integral byte representation, no structural decomposition

**Reason for rejection:** golden replay is not a structural solution. The fixture bytes were hard-coded, not derived from tables or formatters. The design could not generalize to other fixtures without regenerating the entire table.

### Decimal formatter (0–99)
- `decimal_tens_byte(n)` — recursive, subtracts 10 until n < 10, returns ASCII tens digit
- `decimal_ones_byte(n)` — recursive match for 0–9 lookup, subtracts 10 for larger values
- `decimal_length(n)` — returns 1 (n ≤ 9) or 2 (n ≥ 10)

### Structural emission primitives (in main)
- `write_byte(val)` — `buffer_low[cursor_low] = val; cursor_low++`
- `write_fragment(id)` — emits each byte of a fragment via `fragment_byte(id, i)`
- `write_symbol(id)` — emits each byte of a symbol via `symbol_byte(id, i)`
- `write_opcode(id)` — emits each byte of an opcode via `opcode_byte(id, i)`
- `write_decimal(n)` — emits decimal digits via `decimal_tens_byte` / `decimal_ones_byte`
- `write_space()` / `write_comma()` / `write_arrow()` / `write_newline()` / `write_colon()` — inline byte literals for structural punctuation

### Dual-buffer strategy
- `buffer_low[0..299]` — first 300 bytes
- `buffer_high[0..147]` — remaining 148 bytes (tryte index limited to 364 max)
- Test reconstructs output by concatenating non-zero, non-None values

### `compare --check` exit code
Returns `1` because `sign` fixture is not implemented. This is the expected behavior.

### No arbitrary replay
- All bytes are computed from structural tables (`fragment_byte`, `symbol_byte`, `opcode_byte`) or the decimal formatter
- No fixture-specific byte is hard-coded in `main()`
- No generator script is versioned in the repository
- The design generalizes: adding a new fixture requires only table entries + new line sequences in `main()`

# ADR-0037: M1.51 Composite Owned Values and Aggregate Ownership ABI

Status: Accepted for architecture closure only. M1.51 language/compiler
implementation is not started by this decision.

## Context

M1.39 through M1.41 define owned bytes, text, vectors, maps, and sets as
closed dynamic value families. Records, enums, and fixed arrays already have
deterministic nominal and fixed-value layout contracts, but the current
implementation rejects dynamic leaves inside those aggregates. The next
implementation campaign needs one ownership unit, one layout model, one
internal call convention, and one cleanup contract before semantic or backend
changes are attempted.

The current IR, emulator, and native backend contain useful precedents:
semantic fixed-value layouts provide ordered logical cells; IR and Assembly
already support ordered multi-cell results; and x86-64 already has a hidden
caller-provided result area for internal aggregate results. Those precedents
do not themselves implement owned aggregates. This ADR closes the architecture
without changing those components.

## Decision

M1.51 uses a **whole aggregate** as the ownership unit. A record, enum payload,
static array, or nested fixed aggregate containing supported owned leaves is
one linear owned value. The aggregate owns every owned leaf reachable through
its declared layout.

The supported aggregate forms are:

- records;
- enum payloads;
- static arrays;
- nested fixed aggregates composed from the forms above.

The supported owned leaves are `bytes`, `text`, `tryte_vector`, `i64_vector`,
`f64_vector`, `i64_map`, and `i64_set`. Dynamic collections whose elements are
arbitrary owned aggregates, such as `vector<User>` or `map<Key, User>`, are
outside M1.51 and require later generic collection work.

## Layout

The language layout is target-independent and consists of inline declared
fields. Fields appear in declaration order. Physical placement uses the
target's native alignment and deterministic `align_up` rules; the aggregate
alignment is the maximum field alignment and tail padding is deterministic.
There is no outer aggregate descriptor.

An x86-64 dynamic leaf is physically represented by a private descriptor with
`base`, `length`, and `capacity`, each a 64-bit word. Its size is 24 bytes and
its alignment is 8 bytes. This is a backend storage contract, not a public
language pointer, not a universal S3 ABI, and not a C layout promise. The base
word is never exposed as an S3 raw pointer.

Static arrays use contiguous elements with an aligned element stride and are
destroyed in reverse index order. Enums retain the existing discriminant and
aligned active payload model. Only the active payload is destroyed.

## Internal call and return ABI

An owned aggregate parameter is passed indirectly through a backend-owned
storage address or slot. The source language has no address value and cannot
observe or store that address. Passing an owned aggregate transfers ownership
to the callee and is destructive at the caller.

An owned aggregate result uses a caller-provided result slot, equivalent to the
existing hidden sret precedent for multi-cell internal results. The callee
constructs the result in that slot and ownership of the completed aggregate is
transferred to the caller. The hidden slot is an internal compiler/backend
mechanism, not a source parameter and not a C ABI.

The descriptor ABI is therefore closed for architecture purposes:

`AGGREGATE_DESCRIPTOR_ABI_STATUS=CLOSED`

The implementation must preserve hosted/emulator and native meaning; neither
backend may make physical addresses observable.

## Move, borrow, replacement, clone, and drop

Moving an aggregate destructively transfers the whole aggregate. M1.51 does
not require a runtime moved flag or zero-after-move. A moved source is rejected
by semantic ownership analysis. Partial field moves are forbidden.

Field borrows are lexical projections of the aggregate borrow. A shared field
borrow may coexist with other shared borrows; one mutable field borrow excludes
all other borrows that could overlap. An active field borrow blocks whole-value
move and drop. These are language rules; no machine `noalias` guarantee is
introduced.

Owned field replacement evaluates the new value completely, then drops the old
field, then moves the new value into the field. Failure before the replacement
is complete leaves the old aggregate valid. Public partial initialization and
runtime initialization bitmasks are not introduced.

Clone is an explicit deep recursive clone. `bytes` and `text` preserve exact
logical length and use their specified clone-capacity contract. Vector, map,
and set leaves preserve source capacity. If cloning fails after destination
fields have been created, those destination fields are dropped exactly once;
the source remains valid.

Drop glue is compiler-generated, static, recursive, and exactly once. Records
drop fields in reverse declaration order. Arrays drop elements in reverse
index order. Enums drop only the active payload, using the payload's recursive
order. No GC, reference counting, or ownership type erasure is introduced.

## Control flow and implementation boundary

M1.51 tracks ownership at whole-aggregate granularity. Joins and loop
backedges require equal whole-aggregate ownership states. Field-sensitive,
path-dependent move, borrow, drop, and conditional reinitialization are
reserved for M1.52. M1.51 does not expose partial initialization as a public
value and does not add general generics.

Owned aggregates cannot cross a C boundary. Existing scalar and borrowed-view
FFI contracts remain valid; C never receives or returns an S3-owned aggregate.
Existing 64 MiB/default logical resource limits remain in force and no new
aggregate-global limit is introduced.

Optimizers must preserve O0 ownership semantics and O1 equivalence. No
ownership-eliding optimizer is authorized by this ADR. Deterministic type
identity, field order, layout identity, drop order, clone order, diagnostics,
and IR metadata may not depend on addresses, source paths, timestamps, random
hashes, or allocation history.

## M1.51/M1.52 boundary

M1.51 owns the aggregate value model, legal aggregate composition, whole-value
operations, field borrow projection, replacement transaction, recursive clone
and drop contracts, indirect parameter transfer, caller-provided result slot,
and deterministic target layout metadata.

M1.52 owns field-sensitive path-dependent ownership flow: partial field moves,
conditional reinitialization, path-sensitive state at joins and backedges,
edge cleanup normalization, and verifier-complete exactly-once cleanup across
all control-flow exits. M1.52 may consume this ADR but may not silently change
the aggregate layout or C-boundary policy.

## Implementation map

The future implementation campaign must update these ownership boundaries as a
coherent dependency sequence, without introducing a second source of truth:

| Area | Existing authority / planned responsibility |
| --- | --- |
| Parser | `bootstrap/s3/parser.py` aggregate declarations and `_parse_type`; no new syntax is authorized here. |
| Semantic | `bootstrap/s3/semantic.py` legality, nominal identity, whole-aggregate state, field projections, and diagnostics. |
| Type system | `bootstrap/s3/ast.py` declarations plus semantic owned-aggregate metadata. |
| IR | `bootstrap/s3/ir.py` typed aggregate identity and explicit ownership operations; no untyped collapse. |
| SSA/verifier | `bootstrap/s3/ssa.py` and `bootstrap/s3/verifier.py` preserve group identity and whole-aggregate states; M1.52 adds path sensitivity. |
| Lowering | `bootstrap/s3/lowering.py` construction, indirect parameters, result slots, projection, replacement, clone, and drop glue. |
| Emulator | `bootstrap/s3/ir_emulator.py` and `bootstrap/s3/emulator.py` provide the reference ownership oracle. |
| x86-64 | `backends/x86_64/layout.py`, `emitter.py`, and `registers.py` materialize the private aligned descriptor/slot ABI. |
| FFI | `bootstrap/s3/ffi.py` and `python_buffer_abi.py` preserve scalar/view-only boundaries and reject owned aggregate transfer. |
| Tests | Existing composite, enum, fixed-array, aggregate-result, dynamic-buffer, and ordered-collection tests remain regression authorities; new M1.51 tests must cover the closure matrix. |

No file in this map is modified by this architecture ADR. Implementation
ordering and test categories are recorded in the M1.51 milestone and closure
report.

## Consequences

This decision permits a future implementation to make dynamic leaves ordinary
members of explicit aggregates without inventing a public pointer, GC, shared
ownership, or generic collection system. It requires coordinated semantic,
IR, lowering, emulator, verifier, and native work. It also makes M1.52 an
explicit control-flow milestone rather than an undocumented extension of the
layout campaign.

## Rejected alternatives

- A separate outer aggregate descriptor was rejected because it adds an
  unnecessary ownership indirection and obscures field layout.
- A public pointer or C-compatible aggregate ABI was rejected because it would
  expose addresses and create an ownership boundary not present in S3.
- Partial field moves in M1.51 were rejected because they require the
  path-sensitive state machine reserved for M1.52.
- GC or reference counting was rejected because the selected model is explicit
  ownership with static recursive cleanup.
- Generic collections of arbitrary owned aggregates were rejected because
  generic identity and specialization are later architecture work.

# ADR-0028: M1.40 Deterministic Ordered Collections

Status: Accepted

## Context

M1.39 closed the ownership, allocation, borrowing, and private descriptor
contract for bytes and text. S3 still has no reusable ordered collection that
can hold a growing numeric sequence. Fixed arrays remain intentionally bounded
and statically laid out.

M1.40 must add useful collection storage without introducing general
parametric generics, implicit sharing, a second allocator model, or a public
pointer representation.

## Decision

M1.40 adds three closed source types:

    tryte_vector
    i64_vector
    f64_vector

The names are built-in type names, not instantiations of a generic type.
GENERAL_PARAMETRIC_GENERICS=NO.

Each value is an ordinary move-only owner using the M1.39 allocator and borrow
rules. Assignment, parameter passing, and return move the owner.
vector_clone is the explicit deep-copy operation. A vector owns a contiguous
ordered sequence; its logical length and capacity are element counts. reserve
takes an exact element capacity and never shrinks. push never grows
implicitly. pop, indexing, and set are checked.

The element layouts are closed and fixed:

- tryte_vector: signed tryte values, two native payload bytes per element;
- i64_vector: signed i64 values, eight native payload bytes per element;
- f64_vector: IEEE-754 f64 values, eight native payload bytes per element.

The physical descriptor remains private. The native implementation may store
byte length and byte capacity and derive element counts from the closed
operation family; source code cannot inspect addresses, descriptors, or
element widths.

## Alternatives

| Option | Safety | Determinism | M1.39 fit | Native complexity | Generic dependence | Decision |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| A. Closed type-specific vectors | 5 | 5 | 5 | 4 | 5 | Selected |
| B. Public Vector<T> | 4 | 5 | 3 | 3 | 1 | Rejected: introduces generics |
| C. One untyped byte container | 2 | 4 | 3 | 4 | 5 | Rejected: loses element contracts |

Option A is selected because it preserves the M1.39 ownership and descriptor
model while giving numeric workloads a statically checkable element type.
Option B is rejected by the roadmap generics firewall. Option C would move
range and representation errors from semantic analysis into runtime code.

## Failure and invalidation policy

Allocation, capacity arithmetic, vector-full, bounds, and element-range
failures use deterministic runtime traps. M1.42 remains responsible for
structured result/error values. Shared or mutable borrow conflicts and
use-after-move remain semantic diagnostics. A reserve that reallocates is
forbidden while any borrow of the owner is active. clone and slice create
independent owned values; slice is not a view.

## Boundary

M1.40 owns ordered numeric vectors, explicit growth, deterministic indexed
access, and the differential/native collection gate. M1.41 owns maps and sets.
M1.42 owns structured error transport. M1.40 does not add hash tables,
iterators with hidden aliasing, records as elements, nested owners, or
concurrent mutation.

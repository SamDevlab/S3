# ADR-0032: M1.44 Small Layered Standard Library

Status: Accepted

## Decision

S3's first standard-library surface is a small, versioned set of source
modules under `s3.v1`:

- `s3.v1.core` for capability-free scalar helpers;
- `s3.v1.text` for text construction and queries;
- `s3.v1.collections` for ordered map and set wrappers;
- `s3.v1.io` for explicit resource operations;
- `s3.v1.host` for explicit capability grant and resource opening.

The compiler exposes a manifest and an explicit module selector. Module IDs,
exports, source paths, and capability metadata are deterministic and sorted.
The loader rejects unsupported versions and unknown module IDs.

Only `s3.v1.host` and `s3.v1.io` declare the `resource` capability. Importing
or using those modules does not grant ambient authority; the program must
pass the capability and handle values explicitly. The source modules are
wrappers over the existing closed builtins and do not add generic syntax,
exceptions, or hidden host access.

## Compatibility policy

`s3.v1` is a frozen compatibility surface for this milestone. Incompatible
changes require a new versioned module namespace, such as `s3.v2`; additive
APIs must still be recorded in the manifest and specification. A program may
select the exact module set it needs, and wildcard or implicit module loading
is not part of the contract.

## Consequences

The hosted compiler and Linux x86-64 native path share the same source module
contract. Capability metadata can be audited before compilation, and module
selection keeps unused host wrappers out of the source input. A package
registry, locale database, and general-purpose object wrapper layer remain
outside M1.44.

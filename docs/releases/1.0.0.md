## What S3 1.0 represents

S3 1.0 is the first stable release decision for the current reference toolchain line. The Python implementation remains the reference/default compiler.

The canonical line includes the currently documented compiler and runtime capabilities, including:

- balanced `trit` and `tryte` types;
- checked `i64` and IEEE-754 `f64` support;
- functions, recursion, loops, `match`, arrays, records, enums and modules;
- typed references and explicit mutability contracts;
- typed IR, CFG/SSA verification and conservative optimization;
- S3 Assembly plus hosted emulation;
- Linux x86-64 native generation within the certified contract;
- deterministic diagnostics, artifact/version contracts and differential testing;
- package, trust, network, FFI and developer-tooling surfaces only within their documented evidence boundaries.

## Support and certification boundaries

Stable 1.0 must preserve the distinction between implementation and certification:

- Linux x86-64 native claims are limited to certified contracts;
- Windows hosted/native claims are stated only where current evidence supports them;
- AArch64 and macOS ARM64 structural evidence is not promoted to runtime certification;
- TLS/crypto/provider-dependent paths remain fail closed when a vetted provider is unavailable;
- benchmark timing remains characterization unless an equivalent native comparative protocol is certified;
- full compiler self-hosting is a separate deferred research frontier and is not a 1.0 release gate.

## RC2-to-stable policy

The stable line is feature-frozen. Before publication, only release-scope changes are allowed:

- correctness and security repairs;
- deterministic/reproducibility repairs;
- packaging and installation fixes;
- release documentation;
- bounded test/CI repairs that do not weaken gates.

No new language/runtime capability train is part of the stable 1.0 preparation.
